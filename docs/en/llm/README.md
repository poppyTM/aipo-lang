# Aipo — canonical engineering and coding guide for LLMs

This directory contains the formal specification, negative/positive grammatical rules, clean-code
patterns and project architectures aimed at language models (LLMs) coding in **Aipo V1** without
hallucinations.

---

## 1. Why does this guide exist?

Modern language models (Claude, GPT-4o, DeepSeek, Gemini, Llama) were trained on billions of
lines of Python, JavaScript, C, C++, Rust and Go. Since Aipo is a language with syntactic
conventions deliberately designed for low cognitive overhead and neurodivergence (ADR-001):

1. **Aipo does not exist in LLM pre-training:** the model tries to operate by analogy with other
   languages.
2. **Strong biases cause fatal errors:**
   - The LLM tries to use `//` for comments (in Aipo, `//` is integer division).
   - The LLM tries to use `for item in lista` (in Aipo, `for` does not exist; use
     `each item in lista`).
   - The LLM tries to use `try / catch / throw` (in Aipo, use `attempt / failed` and `fail`).
   - The LLM tries to use `class` or `impl Tipo { fn metodo() }` (in Aipo, use pure `struct`
     and association `Tipo:metodo()`).
   - The LLM tries to use `&&` and `||` (in Aipo, logical operators are whole words: `and` and
     `or`).
3. **Evolving dialect:** the previous compiler accepted `end`, `div`, `self!`, `impl` and
   `satisfy`. Canonical V1 **removed** all of these forms. This guide shields the LLM against
   legacy dialects.

## 2. Structure of this guide

| Document | Focus | Recommended use |
|---|---|---|
| [`rules.md`](rules.md) | **Positive and negative rules** | Immediate prohibition table, "From → To" mapping, critical pitfalls and strict grammar. |
| [`clean-code.md`](clean-code.md) | **Clean code & cognitive design** | Cognitive-clarity principles, immutable-by-default data modeling, contracts (`invariant`, `#!satisfies`), transactional error handling. |
| [`project-structure.md`](project-structure.md) | **Project organization** | Complete structural patterns for **applications** (CLI, backend/API, GUI) and **libraries / modules / frameworks** (`aipo.toml`, exports, tests). |
| [`cheatsheet.md`](cheatsheet.md) | **Cheat sheet for context injection** | Ultra-dense version (< 120 lines) ideal for injection into system prompts or project rules (`.cursorrules`, `CLAUDE.md`, Custom GPTs). |

## 3. Skill and tools for agents

Beyond the static documentation, the repository provides the official `lang-aipo` skill:

- **Skill definition:** `skills/lang-aipo/SKILL.md` (and registered in
  `~/.claude/skills/lang-aipo/`).
- **Canonical examples:** `skills/lang-aipo/examples/` (tested, parseable code covering apps,
  libs, async and transactions).
- **Knowledge base:** `skills/lang-aipo/knowledge/` (stdlib inventory and syntax matrix).
- **Validation script:** `skills/lang-aipo/scripts/lint_aipo.py` (lexical linter for quick
  checking of forbidden tokens generated by LLMs).
- **Platform adapters:** `skills/lang-aipo/adapters/` (ready-to-use instructions for Claude, GPT,
  OpenCode and generic providers).

---

## 4. LLM consultation order

When an LLM is tasked with reading, generating or refactoring Aipo code:
1. Load [`cheatsheet.md`](cheatsheet.md) or activate the `lang-aipo` skill.
2. Check [`rules.md`](rules.md) for sanitization against forbidden words.
3. Follow the modularity conventions in [`project-structure.md`](project-structure.md).
4. In case of doubt about fundamental decisions, consult the canonical reference in
   [`../../SYNTAX.md`](../../SYNTAX.md) and
   [`../decisions/adr-001-canonical-syntax.md`](../decisions/adr-001-canonical-syntax.md).
